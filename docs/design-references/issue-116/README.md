## 参考冲突的裁决

两份参考互补，不要求像素级照搬。出现差异时按以下规则解释：

1. HTML 参考优先确定 TradePulse 外壳、横向筛选结构、进入/退出后台配置、权限表和响应式行为。
2. PNG 参考优先确定身份预览、页签、基础条件、完整七类标签、已应用条件、结果数和客户预览的信息层级。
3. 同一标签分类内多选是 **OR（或）**，不同分类之间是 **AND（且）**。
4. 用户勾选、取消或编辑的条件先写入待应用状态；点击“应用筛选”后才更新正式结果数和业务列表。
5. “清空”同时清除待应用条件和已应用条件，并恢复未筛选结果。
6. 成员例外权限只能在权限组默认值上做加法，或恢复组默认；不能用个人设置否定权限组已经授予的筛选项。
7. 权限配置、身份预览和人员/权限组选择器只能出现在“用户与权限”页，业务列表页不得出现这些后台入口。
8. 分类数、选项数、命中数和结果数均来自服务器返回的 schema/数据，禁止硬编码参考图中的 `7`、`74`、`4` 等展示数字。

## 七类标签

标签筛选必须由服务端授权后的 schema 驱动，分类名称固定为：

1. 客户类型
2. 客户经营产品
3. 应用行业
4. 需求/采购产品
5. 重点场景
6. 需确认属性
7. 名单标签

前端只能加载服务端明确授权的字段、运算符和值。搜索框的提示文案与搜索范围也必须受当前身份可搜索字段约束，不能通过全文搜索绕过联系人、管理评价等敏感字段权限。

## 状态与失败路径

- 待应用条件可在本地即时更新摘要，但正式结果数和客户列表只在“应用筛选”成功后更新。
- schema 版本或权限版本变化时，客户端必须重新校验条件；已经撤销的筛选项不得继续请求、恢复或导出。
- 导出必须复用与列表查询相同的授权校验，不能另建宽松的筛选解析路径。
- 必须覆盖加载中、无可用筛选项、无筛选条件、零结果、保存中、保存失败、schema 过期和权限被撤销状态。
- 服务端只接受注册表/allowlist 中的字段与运算符；schema 不得暴露任意列名、SQL 片段或未授权选项。

## 桌面端验收（1440 × 900）

- [ ] TradePulse 导航、标题、操作区和横向筛选区层级清楚，首屏主要业务列表仍可见。
- [ ] 基础条件与七类标签名称对齐；选项按可用宽度自然换行，没有遮挡或横向溢出。
- [ ] 卡片和边框克制，筛选状态、已应用条件、结果数和主操作形成明确视觉顺序。
- [ ] “用户与权限”页可进入筛选权限配置，并可查看权限组、个人例外和身份预览。
- [ ] 权限表的字段名称、可见/可用状态和恢复组默认操作可辨识。
- [ ] 已应用条件支持逐项移除和全部清空；结果条、分页与列表不重叠。
- [ ] 任意业务列表页都没有权限配置、身份预览或人员选择入口。

## 移动端验收（390 × 844）

- [ ] 页面标题、结果摘要和操作按钮按纵向堆叠，主操作保持可达且不覆盖内容。
- [ ] 分类标签位于选项上方，选项可换行或滚动，不依赖悬停。
- [ ] 后台配置的身份、权限组和成员选择器为单列布局。
- [ ] 权限表在窄屏可横向滚动，表头与单元格不被裁切。
- [ ] 已应用条件始终可见，支持单项移除和清空，长文本不会撑破视口。
- [ ] 加载、空状态、零结果、保存失败和权限撤销提示在窄屏可完整阅读。

## Issue 边界

- **#111**：已关闭并合并到 #116。统一筛选组件、客户全景和销售漏斗等业务页面对公共筛选能力的需求，以 #116 的 schema、组件和授权规则为唯一基线，不重复实现另一套筛选框架。
- **#113**：继续独立跟踪回收站专属的筛选项、分页和“三类数量”口径。#113 必须复用 #116 的 schema、状态模型、组件和授权校验；回收站业务语义与数量计算不纳入 #116。

## 实施约束

- 页面可用筛选项来自服务端 feature/field registry 与当前身份授权结果。
- 客户列表及其结果数必须走服务端分页 API，不能下载全量数据后在浏览器中完成主筛选。
- 保存后台配置后应使权限版本失效；其他会话不得继续使用旧授权。
- 列表、结果数、选项计数与导出使用同一套安全编译和授权判定。
- 本目录中的 HTML 与 PNG 必须保持上述哈希；如需更新设计，应新增经确认的版本，而不是静默覆盖。
