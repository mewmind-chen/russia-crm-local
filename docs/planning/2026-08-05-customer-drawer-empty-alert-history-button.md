- 关联 Issue：[#227 区分客户创建人与领取人，并增加客户历史](https://github.com/mewmind-chen/russia-crm-local/issues/227)

- 影响页面：CRM 客户全景 -> 客户详情抽屉
- 影响角色：无 `view_contacts` 权限但可查看客户的账号

## 用户反馈

客户详情抽屉顶部出现一个只有红色边框和空胶囊的区域，不知道表示什么；底部“查看客户历史”点击后看起来没有任何反应，像一个没有实现的假按钮。

截图中可以同时观察到：

- `NEXT ACTION` 上方存在一张没有标题、说明和动作文字的异常提醒卡；
- “完整客户时间线”已经直接展示 6 条记录；
- 同一区域同时存在“查看客户历史”和“展开完整时间线（6 条）”两个相近入口。

## 定位结论

两个现象都有确定的代码原因，但性质不同。

1. 空红框是数据脱敏误伤：异常提醒对象仍存在，但 `title`、`detail`、`action` 等业务展示字段被联系人权限脱敏器删除，前端仍按“对象存在”渲染卡片，最终只剩边框和空胶囊。
2. “查看客户历史”不是完全没有后端实现：Issue #227 已增加接口，当前请求可返回 `200` 和历史时间线；但点击结果被写到现有时间线下方的隐藏容器，页面不滚动、按钮状态不变化，用户当前视口通常没有任何可见变化，因此形成假按钮体验。

## 问题 A：空红框的根因

### 1. 客户抽屉无条件渲染存在的提醒对象

`sales-assets/app.js:7950-7963` 先通过 `alertFor(account.id)` 获取客户异常提醒，然后只判断 `alert` 对象是否存在：

```js
${alert ? `<div class="next-step" ...>
  <div><strong>${esc(alert.title)}</strong><p>${esc(alert.detail)}</p></div>
  <span class="pill ...">${esc(alert.action)}</span>
</div>` : ''}
```

这里没有判断标题、详情和动作文本是否仍存在。只要提醒对象保留了 `code`、`severity` 或 `reasons` 等字段，卡片就会被渲染。

### 2. Bootstrap 对无联系人权限账号执行通用递归脱敏

`lib/sales_crm.js:6831` 定义：

```js
const contactSafe = payload => permissions.view_contacts
  ? payload
  : redactContactFields(payload);
```

`state.data.alerts` 会经过该处理。账号没有 `view_contacts` 权限时，所有嵌套对象都会被 `redactContactFields` 递归过滤。

### 3. 联系人敏感字段集合误包含通用业务字段

`lib/access_control.js:89-111` 的 `CONTACT_KEYS` 不只包含邮箱、电话、联系人姓名等联系人字段，还包含大量通用字段名，包括：

```text
title
summary
detail
action
nextAction
description
reason
```

`lib/access_control.js:588-594` 会把对象键名统一标准化后递归删除这些字段。因此提醒对象中的：

```json
{
  "title": "需要管理者介入",
  "detail": "...",
  "action": "..."
}
```

会被过滤成只剩代码、严重程度和原因数量等非展示字段的对象。

这属于脱敏边界设计错误：联系人权限脱敏器按“字段名称”全局递归过滤，无法区分 `contact.title` 的职位含义与 `alert.title` 的待办标题含义，也无法区分联系人行动建议与业务提醒动作。

### 4. 最小复现结果

以无 `view_contacts` 权限账号读取最新基线 Bootstrap，客户提醒仍存在，但展示字段消失：

```json
{
  "code": "MANAGER_NEEDED",
  "reasonCount": 3,
  "reasons": [
    { "code": "MANAGER_NEEDED" },
    { "code": "NO_NEXT" },
    { "code": "STALE" }
  ],
  "contactPermission": false
}
```

前端随后渲染该对象，便得到截图中的空红框。

## 问题 B：“查看客户历史”为什么像假按钮

### 1. Issue #227 已实现后端历史接口

`lib/sales_crm.js:10956-10964` 注册：

```text
GET /api/sales-crm/accounts/:customerId/history
```

接口先执行客户访问范围校验，再通过 `buildAccountHistory` 生成客户创建、领取、负责人变化、昵称修改等生命周期事件。`test/issue227_creator_timeline.test.js` 也验证了中文事件、变更前后字段和越权 `403`。

本次复现中该接口实际返回 `200`，所以按钮不是纯静态占位，也不是后端路由缺失。

### 2. 点击结果被追加到已有时间线的下方

`sales-assets/app.js:8010-8012` 先直接渲染当前 `timeline`，然后才放置隐藏容器：

```html
<div class="timeline">...</div>
<div id="customerHistoryList" class="customer-history-list hidden"></div>
```

`sales-assets/app.js:10401-10424` 点击“查看客户历史”后：

- 移除 `hidden`；
- 写入“正在读取客户历史…”；
- 请求历史接口；
- 把结果写入 `#customerHistoryList`。

该容器位于已经展示的完整时间线之后。客户已有多条记录时，新内容通常出现在当前抽屉视口下方。

### 3. 没有任何把用户带到结果的交互反馈

当前处理器没有：

- 滚动到 `#customerHistoryList`；
- 打开弹窗或折叠面板；
- 修改按钮文字为“收起历史”或“已加载”；
- 给按钮增加 loading/disabled 状态；
- 显示返回记录数；
- 区分“当前时间线”和“按需客户历史”的数据范围。

因此点击后即使请求成功，当前视口和按钮外观也可能完全不变。

### 4. 同一区域存在功能含义重叠的第二个入口

“查看客户历史”旁边还有“展开完整时间线（N 条）”。后者会真正打开完整时间线弹窗，交互结果明显；前者却把另一组时间线追加在页面底部。

两个入口都使用“历史 / 完整时间线”语义，但交互方式和数据来源不同，页面没有解释差异。用户自然会把反馈不明显的“查看客户历史”判断为假按钮。

## Issue #227 的实施差距

Issue #227 的后端历史能力已经实现，权限校验和基础测试也存在。当前问题集中在前端呈现和回归覆盖：

- 测试只断言源码中存在按钮、文案和 `customerHistoryList`；
- 没有验证点击后结果在用户视口内可见；
- 没有验证加载、成功、空结果和失败状态；
- 没有处理与“展开完整时间线”入口的功能重叠；
- 没有覆盖无 `view_contacts` 权限时异常提醒字段被误删的组合场景。

所以 #227 不是完全未实现，而是“后端功能已落地，前端入口没有形成可感知闭环”。

## 期望行为

### 异常提醒卡

- 无联系人权限不应删除待办提醒的标题、详情和动作文本。
- 联系人敏感字段脱敏应按明确的数据结构或允许列表处理，不能用通用字段名递归误伤业务对象。
- 前端在核心展示字段为空时不应渲染空卡片，并应记录或暴露异常数据状态供排查。
- 修复不能泄露联系人姓名、职位、联系方式、联系人摘要等真实敏感信息。

### 客户历史入口

- 点击后必须立即有可见的加载反馈，并在成功后把用户带到结果。
- 建议将 Issue #227 的生命周期历史并入现有“展开完整时间线”弹窗，按事件类型统一展示；如确需独立入口，应使用明确命名，例如“查看生命周期变更”，并打开独立面板或弹窗。
- 页面应避免两个含义近似、行为不同的历史按钮并排存在。
- 历史记录数、空状态和失败状态必须清楚可见。

## 后续修复方向

1. 拆分联系人字段脱敏与通用对象脱敏，优先采用按响应结构的安全投影或明确允许列表。
2. 从通用 `CONTACT_KEYS` 中移除会误伤全局业务对象的字段名，或限定其只在联系人、Recon 原始结果等指定路径生效。
3. 在前端增加提醒卡完整性保护，避免渲染只有边框的空对象。
4. 合并或重新定义两个历史入口，确保一个用户动作对应一个明确可见结果。
5. 增加真实 DOM 交互测试，而不是只检查源码字符串存在。

## 建议回归场景

1. 有 `view_contacts` 权限账号看到完整提醒卡和授权范围内的联系人信息。
2. 无 `view_contacts` 权限账号仍看到完整业务提醒标题、详情和动作，但看不到联系人敏感字段。
3. `MANAGER_NEEDED`、`NO_NEXT`、`STALE` 单独或合并时，提醒卡均不出现空标题、空详情或空动作胶囊。
4. 无有效提醒时完全不渲染异常卡，不保留空白占位。
5. 点击客户历史后立即显示 loading，成功、空结果和失败状态均在当前视口可见。
6. 生命周期历史接口继续执行客户范围权限校验，越权访问保持 `403`。
7. “查看客户历史”和“展开完整时间线”只保留一个明确主入口，或以清晰命名和不同内容区分。
8. Issue #227 的创建人、首次领取人、当前负责人和历史事件语义保持不变。
