# TradePulse 长期协作协议

更新时间：2026-08-29

## 每次任务开始前

1. 在 `/Users/ylf/Desktop/projects/tradepulse-refactor/after` 读取 `docs/governance/GOAL_PROMPT.md`、`CURRENT_STATE.md` 和本文件。
2. 读取 `sessions/` 最新 checkpoint；历史 session 的旧路径只按历史证据理解。
3. 在中心 clone 执行 `git fetch origin --prune`，核实 `origin/main`。
4. 在 `after/` 核实分支、HEAD、工作区改动和测试基线；不得假设工作区干净。
5. 确认目标、非目标、影响领域、数据路径、权限边界、验证和回滚方式。
6. 复杂或跨领域任务先形成可检查的计划；发现实质歧义时暂停实现。

## 目录与写入规则

- `repo/`：只用于 Git 同步和 worktree 管理，不编辑业务代码。
- `before/`：只读对照，不提交、不运行写入型业务流程。
- `after/`：当前唯一代码、测试和治理文档写入位置。
- 旧 `tradepulse-development`：迁移来源，只读保留，不继续维护双份治理文档。
- 生产目录和生产数据库：未经明确批准绝不触碰。
- runtime：只使用新根目录下显式创建的独立 runtime；环境和数据库路径必须在 session 中记录。

## 执行规则

- 没有明确实现目标时默认只读调查，不改产品行为。
- 修改前读取目标文件和相关测试；不覆盖用户已有改动。
- 一个切片只解决一个可描述的问题，保持外部 API、错误码、权限和数据语义兼容。
- AI 范围保持冻结，不重构、不迁移、不搬运。
- 每个逻辑切片必须有针对性测试；全量测试红灯时不得叠加下一切片。
- 更新文档不能把历史失败改写成成功，也不能把迁移等同于重构完成。
- 未经用户明确要求，不 push、不合并、不部署、不删除旧目录。

## 每次任务结束前记录

- 目标、范围和非目标；
- `origin/main`、当前分支、HEAD 与未提交状态；
- 修改文件和行为变化；
- 测试命令、总数、通过/失败数和失败归因；
- 权限、数据、迁移、依赖和运行时影响；
- 回滚点、风险、阻塞和下一步最小动作；
- 更新 `CURRENT_STATE.md`，新增当次 `sessions/*.md`。

## 强制暂停条件

- 当前已有未解释的业务代码改动或新增测试回归。
- 需求、代码、测试或治理文档相互冲突。
- 不清楚字段、状态、数据真源、权限边界或生产影响。
- 运行时或数据库路径指向旧目录、生产目录或未知位置。
- 需要不可逆迁移、生产写入、部署、push、merge 或目录删除但未获明确授权。
- 连续尝试没有产生新证据，或任务影响了未声明领域。

## 完成定义

“完成”必须同时满足适用项：业务目标满足；API/数据/权限/状态口径一致；专项与全量回归通过；必要的浏览器或迁移验证通过；工作区、文档、风险和回滚记录完整。

测试通过不等于生产验收通过；迁移内容一致不等于开发分支已经可合并。
