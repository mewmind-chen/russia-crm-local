# CRM 前端美化设计规格

## 目标

在不改变业务流程、API 契约、权限模型和客户数据的前提下，将现有
TradePulse CRM 优化为专注、专业的 B2B 业务操作界面。

本次调整的核心不是增加装饰，而是让使用者在日常工作中更快地扫描信息、
理解状态并执行重复操作，同时建立统一、稳定的视觉语言。

实施方式是在现有 HTML、CSS 和 JavaScript 上渐进升级，不引入 React、
Tailwind、shadcn/ui、构建步骤或另一套并行前端。

## 已确认的设计方向

采用专业业务操作界面：

- 使用冷色中性背景和清晰的白色工作面；
- 深青绿色用于品牌和主要操作；
- 蓝色只用于链接和信息类操作；
- 琥珀色用于待处理、临期和提醒状态；
- 红色用于严重、失败和破坏性操作；
- 边框、阴影和圆角保持克制；
- 字体紧凑但可读，适合高频 CRM 工作；
- 使用统一的线性图标替代 Unicode 符号和 Emoji；
- 交互状态保持稳定，不使用缩放、弹跳和位移动画。

已评估并放弃两个方向：

- 完整重写 CSS 虽然初期较快，但会对权限驱动和动态渲染页面带来较高回归风险。
- 迁移到组件框架会扩大任务范围，并重复现有成熟的 DOM、API 和测试契约。

## 范围

### 包含

- CRM 外壳、侧边栏、顶部栏、按钮、输入框、徽标、面板、表格、抽屉、
  弹窗、空状态和反馈状态；
- 驾驶舱的信息层级以及孤立的第七个指标；
- CRM 客户全景和线索池的筛选展示；
- 客户表格和线索表格的可读性；
- 内嵌客户资料概览、Recon 空状态和标签编辑器；
- 从 1024px 到 2174px 的桌面宽度，以及最低 375px 的移动端；
- 将界面中泄漏的内部英文状态值映射为中文展示文本。

### 不包含

- 后端数据模型或 API 变更；
- 权限行为、筛选授权、客户生命周期、分配、Recon 执行或 AI 行为变更；
- 新驾驶舱、新图表、新主题或深色模式；
- 对所有后台管理页面进行全面重设计；
- 修改其他分支或工作树中的用户现有改动。

## 视觉系统

### 颜色令牌

现有 CSS 变量统一为语义化令牌：

| 令牌 | 值 | 用途 |
|---|---|---|
| `--surface-page` | `#F5F7F9` | 应用背景 |
| `--surface-panel` | `#FFFFFF` | 面板、表格、弹窗 |
| `--surface-subtle` | `#F7F9FB` | 表头、分组控件 |
| `--text-primary` | `#18212F` | 标题和正文 |
| `--text-secondary` | `#667085` | 辅助信息 |
| `--border-default` | `#E2E7ED` | 面板、行、输入框边框 |
| `--brand` | `#0F766E` | 主要操作、激活导航 |
| `--brand-hover` | `#0B625B` | 主要操作悬停 |
| `--brand-subtle` | `#E7F5F2` | 激活和选中背景 |
| `--info` | `#2563EB` | 链接和信息状态 |
| `--warning` | `#B7791F` | 临期和待处理状态 |
| `--warning-subtle` | `#FFF8E6` | 提醒背景 |
| `--danger` | `#C2413B` | 破坏性、超期、失败状态 |
| `--danger-subtle` | `#FFF1F0` | 严重状态背景 |

普通工作面不再使用装饰性径向渐变和玻璃效果。颜色必须有稳定的语义，
并且不能成为表达状态的唯一方式。

### 字体

保留系统字体优先的字体栈：

```css
-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
"Noto Sans CJK SC", "Noto Sans SC", sans-serif
```

字体层级：

| 角色 | 字号 | 字重 | 行高 |
|---|---:|---:|---:|
| 页面标题 | 24px | 650 | 1.3 |
| 区块标题 | 18px | 650 | 1.35 |
| 面板标题 | 16px | 650 | 1.4 |
| 正文和控件 | 14px | 400-600 | 1.5 |
| 表格正文 | 13px | 400-600 | 1.45 |
| 元数据和标签 | 12px | 500-600 | 1.45 |
| 特殊微文案 | 11px | 500 | 1.4 |

业务操作文本不得小于 11px。页面标题和面板标题必须有明显层级差异。
字间距为 0。KPI 数值和对比列使用等宽数字。

### 形状、边框和层级

- 标准控件和面板使用 6-8px 圆角；
- 只有状态和紧凑筛选条件使用全圆角；
- 标准面板使用一像素边框，不使用阴影；
- 菜单、抽屉、弹窗和激活的浮层控件可以使用克制的层级阴影；
- 移除嵌套卡片效果，区块内部使用分组行，不再堆叠装饰卡片。

### 交互

- 桌面控件高度至少 40px，移动端至少 44px；
- 悬停、焦点、选中、禁用、加载和破坏性状态必须清晰可辨；
- 动画只允许颜色、透明度、边框和阴影在 150-200ms 内过渡；
- 移除按钮和卡片的缩放或位移效果；
- 键盘焦点使用明显的青绿色焦点环；
- `prefers-reduced-motion` 下关闭非必要动画。

## 外壳和导航

侧边栏保留现有信息架构和权限可见性。导航符号替换为统一的线性图标。
激活项使用浅青绿色背景、青绿色图标、较强文字和三像素激活边。
普通数量使用中性徽标，只有严重数量使用红色。

顶部栏调整为安静的 64px 工作标题栏，页面标题成为最强信息元素。
日常页面移除重复的英文眉题；只有产品名或技术标识确有信息价值时才保留英文。
主要和次要操作采用统一层级，避免多个填充按钮相互竞争。

主工作区保持流式布局，但最大宽度约为 1680px。更宽屏幕下，在侧边栏之后居中，
避免筛选条、漏斗和正文横向拉伸到难以阅读。

## 驾驶舱

驾驶舱保留现有数据和面板：

- 六个生命周期 KPI 保留在第一行；
- `超期 / 待介入` 移到 `需要我处理` 面板标题区，取消孤立的第七张指标卡；
- KPI 标签使用 12px，数值使用 28px 等宽数字，说明使用 12px；
- 漏斗继续使用水平条，但限制可读宽度，使标签、数值和百分比保持关联；
- `需要我处理` 加强行标题和辅助信息，使用明确的严重状态提示，但不整行填红；
- 国家和活动面板与产品其余表格、动态列表保持同一节奏。

## CRM 客户全景和线索池

### 筛选展示

授权筛选控制器及其序列化载荷保持不变，只调整展示和默认展开状态。

始终可见的筛选行包含：

- 关键词搜索；
- 国家；
- 负责人；
- 客户阶段或线索状态；
- 结果数量；
- 应用和详细筛选操作。

其他筛选项进入折叠的高级区域或右侧筛选抽屉。已经应用的高级条件必须继续以
可删除摘要标签展示，避免折叠控件隐藏当前状态。用户可以一次清除全部条件。

大型原生列表框改为紧凑的复选菜单或分组展开控件，同时保留原有筛选控制器。
重复筛选值在展示前去重。客户标签分类默认折叠，并显示已选择数量。

在 1440x900 下，客户表格和线索表格的表头必须无需滚过完整高级筛选目录即可看到。
线索汇总指标不得把主表格推到第二屏以下。

### 表格

- 表头使用 12px 半粗文字和浅中性背景；
- 公司名称使用 14px 半粗文字，作为每行的视觉锚点；
- 正文使用 13px，次要编号、日期和来源使用 12px；
- 行使用分隔线和浅青绿色悬停背景，不使用阴影；
- 官网展示规范化域名和外链图标；
- 产品数组最多显示三个可读标签，其余显示 `+N`；
- 内部英文状态通过现有中文映射展示；
- 状态单元格使用图标或圆点加文字，不能只靠颜色；
- 保留吸顶表头和现有表格内部横向滚动。

## 客户资料

CRM 外层资料工具栏和内嵌工作台契约保持不变。
内嵌概览重新组织为四个分组：

1. 身份与地区；
2. 业务画像与产品需求；
3. 联系渠道；
4. 合规、来源与生命周期时间。

单个字段不再渲染为独立卡片。每个分组使用紧凑的定义行布局，
标签为 12px，值为 14px。空值显示安静的 `暂无`；
连续的可选空字段可以合并，不再形成大量横杠。

桌面端相关定义行可使用两列。375px 下变为单列，不产生横向滚动。
身份标题、资料标签页和可用操作保持清晰区分，不重复显示公司名称。

Recon 空状态使用一个统一线性图标、一段直接说明和一个主要操作。
空状态应有意填充可用区域，不能留下无法解释的空白。

## 标签编辑器

现有标签 ID、权限检查、新建标签行为和保存 API 保持不变：

- 增加搜索框，在客户端过滤可见标签名称；
- 每个分类使用展开区，并显示已选数量和总数；
- 有选中项的分类默认展开，其他分类默认折叠；
- 选中标签使用浅青绿色背景和可见勾选状态；
- 移动端资料页使用吸底操作栏，包含取消和保存；
- 保存操作必须可由键盘和读屏软件使用，并展示加载状态；
- 新建标签表单与预设标签选择区在视觉上分开，但仍属于标签页。

在 375px 下，用户无需返回 2000px 长列表顶部才能保存。

## 空状态、加载和反馈

空状态使用紧凑线性图标、一句状态说明，以及存在恢复或创建路径时的操作按钮。
加载状态应预留最终空间，等待明显时使用骨架行。Toast 使用
`aria-live="polite"`，不抢夺焦点，并保持足够阅读时间。
错误信息需要说明失败原因和下一步恢复操作。

## 响应式行为

验收尺寸为 375x812、768x1024、1024x768、1440x900，以及至少 1920px 宽：

- 所有尺寸都不得出现页面级横向滚动；
- 移动端资料内容必须保持在 iframe 宽度内；
- 列数无法容纳时，表格保留有意设计的内部横向滚动；
- 固定或吸底操作必须为内容预留空间，不得遮挡最后一行；
- 关键客户名称不能在没有查看完整内容途径时被截断。

## 无障碍

- 所有纯图标按钮具有中文无障碍名称，必要时提供工具提示；
- 导航、标签页、展开控件、菜单、抽屉和弹窗可使用键盘操作；
- 焦点顺序与视觉顺序一致；
- 文字和有意义图标达到 WCAG AA 对比度；
- 状态不能只使用颜色表达；
- 尊重减少动画偏好；
- 移动端点击目标至少 44px。

## 实施边界

主要文件：

- `sales-assets/app.css`：外壳、字体、导航、驾驶舱、表格、资料外壳和响应式系统；
- `sales-assets/filter-component.css`：紧凑筛选和高级筛选展示；
- `sales-assets/app.js`：只调整驾驶舱指标分组和展示格式；
- `sales-crm.html`：图标标记和少量语义结构；
- `Index.html`：内嵌资料分组、标签展开区、空状态及相关样式。

JavaScript 必须保留现有元素 ID、事件、权限门控、筛选序列化、API 调用和
`postMessage` 集成。只有在自动化测试记录了有意的标记变更时才允许调整。

## 测试

自动化测试覆盖：

- 视觉令牌和最小字号；
- 语义图标按钮和无障碍名称；
- 六个驾驶舱 KPI 及提醒汇总位置；
- 客户和线索筛选保留控制器载荷与激活状态；
- 高级筛选默认折叠及已应用条件摘要；
- 产品数组和状态展示格式；
- 资料字段分组，同时保留 Issue 127/128 API 字段；
- 标签搜索、分类展开、选中状态和吸底保存；
- 现有权限和资料访问行为。

现有 Issue 116、124、128 和 130 前端测试必须保持通过，完整 Node 测试套件必须通过。

浏览器验证使用带认证、接近生产的数据，在全部目标尺寸检查：

- 驾驶舱；
- CRM 客户全景；
- 线索池；
- 客户资料概览；
- Recon 空状态；
- 标签编辑器。

验证重点是无重叠、表格可见性、滚动范围、焦点状态和内容可读性，
不能只依赖截图外观。

## 验收标准

1. 界面统一使用批准的语义颜色、字体层级、圆角、边框、图标和交互状态。
2. 页面标题与面板标题层级清楚，业务文本不小于 11px。
3. 1440x900 下，无需滚过完整高级筛选目录即可看到客户和线索表头。
4. 1920px 及以上宽度下，主内容和漏斗保持可读宽度。
5. 驾驶舱不存在孤立指标卡，紧急工作仍然突出。
6. 表格展示清晰的公司锚点、规范化官网、产品标签和中文状态。
7. 375px 客户资料无横向滚动，相关字段使用紧凑分组，不再是 19 张独立卡片。
8. 标签选择支持搜索和分组展开，移动端底部始终可以保存。
9. 现有权限、数据、API、筛选、客户生命周期、Recon 和 AI 行为不变。
10. 定向 UI 测试、完整测试套件以及桌面和移动端浏览器验证全部通过。
